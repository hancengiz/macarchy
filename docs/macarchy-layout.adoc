// =========================================================== Options
include::./util/conditional-options-header.adoc[]

-h, --help:: Print help

--window-id <window-id>::
include::./util/window-id-flag-desc.adoc[]

--workspace <workspace>::
include::./util/workspace-flag-desc.adoc[]

--root::
Instead of the focused window, change the layout of the workspace tiling root node.
When you use this flag, `tiling` and `floating` become invalid values for `<target-layout>`.

--fail-if-noop::
Exit with non-zero exit code if already in the requested layout.
When you use this flag, the command permits only one `<target-layout>` argument.

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

<target-layout>::
Possible values:
+
* `h_tiles|v_tiles|h_accordion|v_accordion` - Change both tiling layout and orientation in one go
* `tiles|accordion` - Change tiling layout but preserve orientation
* `scrolling` - Horizontal columns with a viewport that follows focus (this fork)
* `horizontal|vertical` - Change orientation but preserve layout
* `tiling|floating` - Toggle between floating/tiling mode
+
If several `<target-layout>` are supplied, then the first one that doesn't describe the currently active layout is applied.

`scrolling` uses each app's `[app-window-widths]` preference, falling back to
`scrolling-column-width` percent of the container (49 by default; integer range
10 through 100). App preferences use quoted bundle IDs and integer percentages
from 1 through 100. Defaults apply during layout unless the window has an explicit
manual width. `resize width` changes the current column; `balance-sizes` clears
manual overrides in the workspace and restores app defaults or the fallback.
See xref:commands.adoc#save-app-width[save-app-width] to remember a window's width
as an app default. These preferences do not automatically size floating windows.

Partially visible columns retain their full width and true desktop-wide positions.
Adjacent displays may intentionally show overflow: per-monitor clipping and
compositor animation are not implemented. Fully hidden parking minimizes rectangle
intersection across all displays and never moves native-fullscreen windows.
Applications may enforce a larger minimum size than the requested column width.

// =========================================================== Examples
include::./util/conditional-examples-header.adoc[]

* Toggle between `floating` and `tiling` layouts (order of args doesn't matter): +
`macarchy layout floating tiling`

* Toggle orientation (order of args doesn't matter): +
`macarchy layout horizontal vertical`

* Toggle between `tiles` and `accordion` layouts (order of args doesn't matter): +
`macarchy layout tiles accordion`

* Toggle the current workspace between horizontal tiling and scrolling columns: +
`macarchy layout --root scrolling h_tiles`

* Switch to `tiles` layout. Toggle the layout orientation if already in `tiles` layout: +
`macarchy layout tiles horizontal vertical`
